# console

The Next.js console. It displays the phase 4 results and the phase 5 geostationary
window. It does not produce them.

## Running it

    cd apps/console
    npm ci
    npm run dev

The map tiles come from whichever provider `NEXT_PUBLIC_BASEMAP_TILES` names, an
XYZ URL template set in `.env.local`. Without it the map draws no base layer. A
public deployment needs a provider whose terms allow public use.

The data it reads is generated by `scripts/export_console.py`, which writes the
files in `public/data/`. Regenerate them after any change to the model or the
reference layers:

    uv run python scripts/export_console.py

## What it shows

A MapLibre map of the sampled detections, coloured by predicted class. A timeline
scrubber over the acquisition dates. A per detection evidence panel carrying the
class posterior, the conformal prediction set, the applicability domain status,
the recurrence history at that location and the nearest reference asset. A
persistent source panel listing recurring locations with no registry match. CSV
export of whatever the current filters select.

Below the map, the model card: per class F1 by held out group, conformal coverage
against the nominal level, B2, and an explicit list of what is not measured.

## Rules this console follows

**It runs no model.** Every posterior, prediction set and applicability flag was
computed by `scripts/export_console.py` and is read from a file.

**It recomputes nothing.** No aggregation over the detection records happens in
the browser. A number on screen came from `metrics.json` or `manifest.json`,
which are generated from `ml/artifacts/`, which is what `docs/results.md` quotes.
One number, one source.

**It hardcodes nothing.** There is no metric literal anywhere in `app/`,
`components/` or `lib/`.

**Unmeasured values say so.** A quantity the pipeline did not compute renders as
the words `not measured` in a muted style. The component is not hidden and the
value is not replaced by a zero or a dash. The `Not measured` card lists every
blocked baseline with its reason.

**The sample is declared.** The console shows 8246 detections stratified from the
group_a held out states, not the 642970 in the store. The sampling rule is on
screen, because flare is 1.16 percent of the labelled detections inside Indian states and an unstratified sample
would show almost none of it.

**Numbers have a pinned locale.** Counts use the Indian lakh convention through
`count()` in `lib/format.ts` with the locale given explicitly. An unpinned
`toLocaleString` renders the same figure differently depending on the viewer's
machine.

**Attribution renders in the footer**, not only here: NASA FIRMS, Global Energy
Monitor under CC BY 4.0, OpenStreetMap under ODbL 1.0, ESA WorldCover under
CC BY 4.0, and the EOG flare catalogue.

## Constraints

TypeScript strict with `noUncheckedIndexedAccess`. A zod schema at every file
boundary, parsed not cast, because the exporter and the console are separate
programs. Server components by default; one client component, for the map and the
filters. No browser storage APIs.
